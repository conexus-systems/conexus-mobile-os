**Data:** 2026-10-22 · **Status:** inventário pendente. Nenhum flash. Nenhuma imagem existe para este aparelho.

O SoC e o número de modelo precisam ser **lidos do próprio aparelho** (`conexus-installer inventory`), não das fichas.

## O que NÃO foi encontrado (e por isso não é afirmado)

Em 2026-10-22:
- Nenhum repositório `LineageOS` com `tcl` no nome (só `android_external_libtextclassifier`, que não tem relação) e nenhuma busca no GitHub por device tree do 505 ou do `T509K` devolveu resultado.
- O portal de código aberto da TCL não respondeu (`opensource.tcl.com`) e a página alternativa deu 404. **Não confirmei** se a TCL publica a fonte GPL do kernel deste modelo.
- Nenhuma fonte sobre a política de desbloqueio de bootloader dos TCL. **Desconhecido.**
- O codinome interno (`ro.product.device`) do 505 não foi encontrado; não vou inventar um.

## O que isso significa

Não existe "o core" para o TCL 505. O core é uma imagem LineageOS construída para o aparelho, e isso exige device tree, fonte do kernel e blobs de vendor do modelo. Hoje não há nenhum dos três públicos. Por isso:

- O instalador **não consegue** instalar o Conexus no TCL 505 agora: ele só instala uma release publicada para o aparelho, e não há release. Ele vai parar com "nenhuma release encontrada", que é o comportamento correto.
- **Não grave nenhuma imagem de outro aparelho no TCL 505.** Isso pode deixá-lo sem boot.

## O que o módulo de drivers do TCL 505 será

Duas partes, ambas dependentes do aparelho:
1. **Pacote de driver em userspace** (HAL em Rust, ADR-016), escrito depois de saber o SoC e as interfaces do vendor.
2. **Blobs MediaTek do próprio aparelho**, extraídos do seu TCL e **nunca redistribuídos** pelo projeto (ADR-014).

Nenhuma das duas existe ainda. `brands/tcl.json` está `planned` e **sem aparelhos listados**, porque ainda não há codinome nem evidência.

## Próximo passo, que só você consegue fazer

Com o TCL ligado, a depuração USB autorizada e um cabo no computador:

```bash
cd tools/installer
go build -o conexus-installer ./cmd/conexus-installer
./conexus-installer inventory --out tcl505.json
```

O comando só **lê**. Ele não grava nada, não copia arquivos do fabricante e não coleta serial, IMEI nem contas (lista fechada de propriedades). Ele mostra o SoC, o kernel, se o aparelho é A/B, o estado do bootloader e avalia C1–C5 do ADR-010. Mande o `tcl505.json` (ou cole a saída) para a gente decidir:

- **Kernel < 5.10:** aparelho "legado": só driver em userspace, sem módulo de kernel (ADR-010).
- **Bootloader travado e sem opção "Desbloqueio de OEM":** sem como instalar. Fim do caminho para este aparelho.
- **Destravável:** o próximo trabalho é achar a fonte do kernel e montar o device tree, que é o item maior.

## Extrair os arquivos de vendor do seu aparelho

Depois do inventário, e só se o resultado mostrar que vale a pena, copie os arquivos de vendor do **seu** TCL. É o equivalente ao `extract-files` do LineageOS:

```bash
./conexus-installer extract --out ./tcl505-vendor
```

- Só **lê** do aparelho (`adb pull`) e só de uma lista fechada: `/vendor/lib/modules`, `/vendor/lib/hw` e `/vendor/lib64/hw`, `/vendor/bin/hw`, `/vendor/firmware`, `/vendor/etc/init` e `/vendor/etc/vintf`. Nunca lê `/data` nem `/sdcard`.
- Sem root, o Android pode negar parte desses caminhos. O comando lista o que não conseguiu ler; se não copiar nada, avisa.
- A pasta recebe um `.gitignore` com `*`, um `AVISO.txt` e um `extract-manifest.json` com SHA-256 de cada arquivo (sem serial).
- **São arquivos da TCL e da MediaTek. Não os publique nem os envie ao repositório.** O projeto nunca os redistribui (ADR-014).

Com o conteúdo extraído, o próximo trabalho é identificar quais módulos e HALs o aparelho usa para escrever o HAL em Rust e montar o pacote de driver.
